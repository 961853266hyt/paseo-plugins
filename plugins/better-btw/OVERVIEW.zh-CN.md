Better btw 把 Claude Code 的 `/btw` 带到了 Paseo：在不打断 Agent 的情况下，顺便问一个关于它正在做什么的问题，而且不会往它的对话里添加任何内容。

在 Agent 的输入框里输入 `/btw` 加问题，例如 `/btw 刚才那个配置文件叫什么来着？`。Paseo 在应用里执行这个命令，从不把它发给 Agent，所以 Agent 忙着的时候也能用，正在进行的那一轮不受影响。在网页版和桌面版里，回答会流式显示在聊天旁边侧边面板中的“顺便问”面板里，下方有输入框可以接着问。输入框上方还会出现一个跟随回答状态的小标签，iOS 和 Android 应用以及窄窗口就靠它显示回答：小标签显示回答的进度，点一下会在弹出层或底部面板里打开问答记录，里面也有自己的输入框。只输入 `/btw` 会重新打开最近一次的问题；命令中心里的“顺便问 (/btw)”会打开面板。

和 Claude Code 一样：

- 顺便问能看到到目前为止的对话：你的消息、Agent 的回复和思考过程、它的工具调用及输出，包括仍在进行中的那一轮。它没有工具，不能读文件、执行命令或搜索；答案不在对话里时，它会直说，而不是去猜。
- 每个回答只有一次回复。之后的顺便问也能看到之前的问答：每次提问时会带上最近 20 个回答。
- 问答记录不会进入 Agent 的历史。“复制”会以 Markdown 复制回答，“清除之前的”会只保留当前这个问题，“停止”会终止还在生成的回答。回答以 Markdown 渲染。

## 准备工作

需要 Paseo 0.11.2 或更高版本，并且在 daemon 所在的机器上安装并登录 Claude Code CLI（`claude`）。无论你问的是哪个 Agent，顺便问都通过这个 CLI 运行。

在 Paseo 0.13 及以上版本中，插件的文字会跟随应用的语言，显示英文或简体中文；更早的版本显示英文。

## 设置

在“设置 → 插件”里，打开 Better btw 的 ⋯ 菜单并选择“设置”。这个设置由同一主机的所有客户端共享：

- **模型**：“与 Agent 相同”（默认）对 Claude Agent 使用它自己的模型，和 Claude Code 一样；对 Codex、OpenCode 等其他 Agent 使用最新 Sonnet。选择最新 Haiku、最新 Sonnet、最新 Opus，或 Paseo 为 Claude Agent 提供的列表中的某个具体 Claude 模型，则对所有 Agent 生效。Haiku 回答最快；更大的模型会消耗更多 Claude 用量。

修改从下一个问题开始生效，不需要重新加载插件。

## 发送了什么、发到哪里

提问时，插件会从 daemon 读取 Agent 的对话，生成一份最多约 100,000 个字符的记录：先放整个会话里用户和 Agent 的消息，再从新到旧放工具输出和 Agent 的思考过程。较长的会话会保留最初的请求和最新的历史。这份记录、你之前的问答和新问题会交给 daemon 所在机器上的 `claude -p`，由它发送给 Anthropic。这适用于所有 Agent：和 Codex、OpenCode 或其他非 Claude Agent 的对话同样会发给 Anthropic。

这次运行没有工具、没有 MCP 服务器、没有 hooks，也不保存会话，所以它无法操作你的项目，也不会出现在你的 Claude Code 历史里。它不会加载你的 CLAUDE.md、规则或记忆文件。你的 Claude Code 设置仍然生效，因此你在那里配置的网关、代理、Bedrock 或 Vertex，以及 `apiKeyHelper` 都会照常使用。每个问题和其他请求一样计入你的 Claude 用量。Claude Code 自带的 `/btw` 会复用对话的提示缓存，插件做不到，所以每个问题都要为它读取的记录付费。

所有 Agent 加起来最多同时回答三个问题，其余的最多等待一分钟。超过三分钟仍未结束的回答会被停止。

## 限制

- 插件不能自己打开浮层，所以在聊天旁边无法打开面板的地方，也就是 iOS 和 Android 应用以及窄窗口，回答不会直接显示在屏幕上，需要点一下小标签查看。
- 回答是一小段一小段出现的，而不是逐字出现：生成期间，应用每 0.4 秒向 daemon 获取一次。
- 问答记录保存在 daemon 的内存里：daemon 重启或插件重新加载会清空它们，归档 Agent 会删除它的问答记录。
- 顺便问只能看到 Paseo 时间线记录下来的对话内容。
- 输入框里有附件时 `/btw` 不会执行：Paseo 会把这段文字当作普通消息发给 Agent。
